# XPENG Vehicle Card v1.0.4-beta.15 — Owner-approved refinements

**Opt-in prerelease candidate, not a stable `main` merge.** Built on the owner-approved Beta 14 design and the latest feedback from real monitor photos. Publish only after all workflow gates pass.

## Changes since v1.0.4-beta.14

- **Desktop Maintenance:** restored the service and identity panel *beside* the existing vehicle/TPMS view. Next service state, date, remaining days/km, odometer, model year and masked VIN appear **only** when the corresponding Xpengtk/Home Assistant entities publish them. No fabricated service interval.
- **TPMS:** removed the four decorative tire-outline halos while retaining the four actual live pressure values, original overhead vehicle image, unit setting and optional published temperature/air-life attributes. Repositioned the MDI tire glyph on the left readouts.
- **Climate:** retained approved cabin/seat/wheel interactions. Restyled only the fan level slider area as an open, unboxed control without blue/pill glow. Fan step count remains driven by live `number.fan_speed_control` min/max/step; no invented 10-step control.
- **Home shortcuts:** all seven shortcuts use a consistent larger native MDI glyph, including the Climate shortcut; removed the separate rounded bubble behind the XPENG wordmark.
- **Location:** native Home Assistant map now focuses on the *single mapped vehicle tracker* with `default_zoom:16` and `auto_fit:true`, without adding unrelated zones or synthetic GPS coordinates. Zoom depends on actual tracker latitude/longitude.
- **Desktop height:** increased available scene height without creating a second mobile card. Narrow Sections/mobile layout remains stacked and scrollable.
- Existing lake photo, approved XPENG car photos, charging cable/pedestal, cabin colour setting, service calls, permission rules and quick-action toggle logic remain in place.
