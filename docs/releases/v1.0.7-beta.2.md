# XPENG Vehicle Card v1.0.7-beta.2 — Official compact controls

This opt-in beta fixes the three home-screen actions that could show **Unavailable** despite having valid Xpengtk entities: windows, tailgate and charging-port flap.

## What changed
- Resolve Xpengtk compact **cover** entities (`cover.*_windows`, `cover.*_trunk`, `cover.*_charge_port`) and their registry unique IDs (`*_windows_cover`, `*_trunk_cover`, `*_charge_port_cover`).
- Prefer the measured cover state over older, sometimes absent, binary sensors and command buttons.
- Use the official Home Assistant `cover.open_cover` / `cover.close_cover` services, gated **separately by supported_features bits OPEN=1 and CLOSE=2** and the card's access controls.
- For windows, opening means **ventilation**, not fully opening. Existing legacy `vent_windows` button is preferred over `open_windows`.
- Never attempt to close a charging flap while a cable is connected.
- If a cover has an unknown state, show **No data** rather than an unsafe guessed command. If a feature is disabled by Xpengtk permissions or hardware, show **Read only**.
- Legacy Xpengtk installations without cover entities still use their existing binary sensors and paired command buttons.
- No changes to the vehicle's integration settings, command policy or firmware. The climate controls from beta.1 are preserved.

## Verification
Includes independent compact-cover simulations for each of the three covers, both directions, partial permissions, unknown/unavailable states, cable-connected safety and legacy fallback. The beta release workflow also validates the generated HACS bundle, runs frontend regressions and captures actual Chromium dashboard screenshots with compact cover entities.

**Important:** A read-only or missing control is not automatically a bug. Xpengtk may disable actions under Command permissions, and manual charge-port flaps cannot be operated remotely. These controls will remain disabled rather than bypassing integration policy.

## Install
HACS → XPENG Vehicle Card → select prerelease **v1.0.7-beta.2** and refresh the frontend. The stable release is unchanged. The beta has not been physically validated on a vehicle.
