# XPENG Vehicle Card v1.0.4-beta.12 — G6 V2 visual corrections and regression QA

**Opt-in test beta only.** This release builds on `v1.0.4-beta.11` and is intended for owner acceptance testing on the desktop and iPhone Home Assistant dashboard. The existing stable `v1.0.3` and beta.11 remain unchanged and available for rollback.

## Changes specific to beta.12

- Updated G6 V2 visual styling across existing pages (Home, automatic Charging, Climate, TPMS/Maintenance and the seven Custom Functions), without inventing new pages or actions.
- Corrected official MDI vehicle controls: an SUV-side trunk pictogram with direction-specific lift/lower arrows, automotive door-lock/open-lock icons and existing car-door window icons. Keep the exact **Open Trunk** copy.
- Neutral, consistent shortcut icon colors with working phone/Sections responsive behavior and a dedicated charging image and active green cable.
- Retains the isolated design/runtime architecture and dynamic in-page control help introduced in beta.11.
- Fixed previously failing icon and visual-regression checks; this version must pass the entire release QA gate before it is published.

## Baseline features retained

- **Real design/code separation:** all maintained dashboard CSS now lives in `src/design/xpeng-vehicle-card.css`; vehicle entities, service commands, permissions and existing page-rendering functions are maintained in `src/core/xpeng-vehicle-card.runtime.js`. A deterministic build (`node tools/build_vehicle_card.mjs`) produces byte-identical, self-contained `src/` and `dist/` JavaScript. HACS still installs a **single card file** — no extra CSS resource is required.
- **English contextual help inside destination pages:** each existing Custom Functions section (X-Guard, Schedule Climate, Energy Data, V2L, Maintenance, Software Updates, Entity Diagnostics) shows a short explanation **inside the opened panel**, not on the shortcut tile. Explanations also appear inside existing Charge Limit, Charge Schedule, Climate, Charge Port, Doors, Windows, Trunk and Location panels.
- **Live min/max instead of guessed limits:** X-Guard security sensitivity, V2L tailgate power timer and charging target use the real Home Assistant `number` entity's `min`/`max`/current attributes. If unavailable, the display explicitly says **Not provided** / **Unavailable**. Read-only data is not misrepresented as a configurable number range.
- **Responsive explanatory pages:** compact charging dialogs and narrow phone/Sections modal views can scroll to reach the last control without clipping the original cabin photo, compromising seat/wheel hotspots or dropping the seven existing functions.
- **Existing visual polish retained:** desktop battery size, matching dark glass surfaces and amber heating / cyan ventilation presentation. Keep original approved car art and night-lakeside background.

## Unchanged vehicle behaviors — critical acceptance

- Home and dedicated Charging scene, automatically switched by **confirmed real charging state**. The original approved charging car orientation, pedestal and thin green-when-active cable remain.
- Same seven home and charging shortcuts, same navigation/back-stack, top-right gear/Custom Functions entry, sensor mapping and permission checks.
- State-dependent Open/Close and Lock/Unlock commands use real Xpengtk entities. Unknown/unavailable states are not turned into fake successful actions.
- Climate seat and wheel actions, diagnostics, maintenance and native Home Assistant location integration remain existing features. No new vehicle command or unsupported feature is introduced.
- No real vehicle command is sent by simulated browser tests. An accepted Home Assistant service call does **not** confirm that the physical car performed an action.

## Verification

This prerelease publishing workflow blocks publication unless source/build integrity, existing control and charging regressions, HACS validation, vehicle artwork provenance, simulated Playwright desktop/iPhone/Sections browser acceptance, and the full 12-image screenshot set all pass. Real iPhone companion-app behavior and physical vehicle actions still require owner testing.

## Installing and rolling back

1. Home Assistant → **HACS** → **XPENG Vehicle Card** → **⋮** → **Redownload** → **Need a different version?**
2. Select `v1.0.4-beta.12` and confirm. Refresh the dashboard browser / restart the mobile companion view to clear cached frontend code.
3. Check the Home screen, automatic Charging, Climate, Maintenance, gear → More Options → X-Guard, V2L and Charge Limit, in both desktop and iPhone sizes.
4. To roll back at any time, select `v1.0.4-beta.11` or stable `v1.0.3` in the same HACS version selector.

No merge to `main` is part of this beta release. The owner should approve the visual layout and verify commands safely while the car is parked before any stable release.
