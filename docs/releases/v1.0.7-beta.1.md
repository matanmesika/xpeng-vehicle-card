# XPENG Vehicle Card v1.0.7-beta.1 — Climate controls

This is an **opt-in prerelease** for testing the seven G6 climate functions with Xpengtk 0.6.28+.

## What's new
- Maximum cooling, maximum heating, air refresh, sterilisation, A/C cleaning, rear-window defrost and Pet mode become **interactive On/Off tiles** when Xpengtk explicitly publishes `control_allowed: true` and the current switch state is `on` or `off`.
- Sends `switch.turn_on` or `switch.turn_off` to the **specific resolved entity**. Does not use blind `toggle` for these modes.
- Matches Xpengtk's canonical `climate_*` unique IDs to the English entity names shown in Home Assistant, including `rear_window_defroster`.
- When a mode is missing, unavailable, unsupported, read-only or its capability cannot be verified, **no command button is shown**. Known entities fall back to a status-only tile.
- Existing front defrost, mirror heating, cabin climate, seat controls and the v1.0.6 charging layout remain unchanged.

## Important compatibility
The upstream Xpengtk implementation publishes `control_allowed` after checking both the vehicle capability and command policy. Older integrations (including the older 0.6.17 fork) may not expose this attribute; those switches will **remain read-only** in this beta rather than sending unverified commands.

## Testing
- Seven independent mode render and command-routing simulations.
- Guard tests for disabled policy, unsupported feature, missing/unknown state and unrecognized switch.
- Full frontend regression, generated bundle consistency and Chromium desktop/mobile responsive checks run in GitHub Actions.

**These are simulated Home Assistant states.** Actual G6 command execution and support must still be verified on a parked vehicle, one function at a time.

## Install
In HACS, enable beta/prerelease versions for XPENG Vehicle Card and select **v1.0.7-beta.1**. Refresh the Home Assistant frontend. Roll back to stable **v1.0.6** if needed.
